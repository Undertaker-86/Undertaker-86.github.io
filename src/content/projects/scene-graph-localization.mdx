## Problem

A robot that localizes against an object-level map (a 3D scene graph) can be wrong in two ways. It can be wrong and
know it, which is harmless because it asks again. Or it can be **wrong and confident**, which is how robots drive
into walls. Maps built by systems like Hydra are themselves uncertain: objects drift with odometry error, and chairs
move between visits.

**Hypothesis.** In a sequential semantic particle filter (SG2Loc-style), model the map's object-placement uncertainty
compactly as a few **shared 4-DoF group transforms plus per-object residuals**, and integrate over it as a persistent
latent. This should cut confidently wrong localizations compared with a fixed map, a temperature-tuned fixed map, and
independent per-object noise.

I worked to the standards I'd expect from a paper reviewer:

- **Splits and decision rules fixed before each run**, with locked test sets opened once (502 sequences in the first
  test round, 836 in the second).
- **Common random particles**, so every model reports the *same* pose and differs only in confidence. Every comparison
  is exactly paired.
- **Strong controls, not just the baseline.** A plain filter rerun with a different seed, a tempered plain filter, and
  independent noise of the same size as the map model. If those match the map model, the map model is not the
  reason.

## Results

**The map model did not beat the plain filter on real data.** On fresh 3RScan and RIO10 test rooms it was never
significantly worse, but never significantly better, and it tied the simple controls. Under large smooth drift (Hydra)
it helped, but a tempered plain filter helped just as much. The study shows why:

1. **Half the apparent gap was particle-filter noise.** Rerunning the plain filter with another seed flips success
   on 10–12 % of queries.
2. **A better confidence signal.** I replaced "mass of the coarse search" with a *chain* confidence (coarse mass near
   the answer × fine mass near the answer). This helps every model, plain included.
3. **The observations are the bottleneck, and simulation hid it.** On real images 84 % of wall/floor patches get an
   object label and 46 % of object patches get the wrong object. The simulator confused only 20 %.
4. **Fixing the labels was the biggest win.** Structure-aware labels (a patch that best matches a wall or floor gets
   no object label) cut spurious labels from 0.84 to 0.12 on 3RScan.

## What I learned

- **A clean negative result is a result.** "Map-geometry uncertainty is not what makes this localizer confidently
  wrong; label noise and visible-object count are" is a useful finding for the next person.
- **Controls beat baselines.** Without the seed-B and tempered controls, several runs would have looked like wins
  for my model.
- **Measure the real noise before trusting a simulator.** One measurement of real label noise changed which
  direction the whole project should go.
