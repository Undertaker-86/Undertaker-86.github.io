## Problem

Cameras struggle with distance, so self-driving stacks lean on LiDAR to place cars accurately in 3D. A LiDAR scan is an
unordered, sparse set of points that gets sparser with range. A detector has to propose boxes and then refine their
centre, size and heading precisely enough to pass a strict IoU test, including for distant, partly occluded
("hard") cars.

The Problem 3 question was how to present pooled points to the refinement network. I ran a four-way ablation, each
for 35 epochs with the same seed on an RTX 5080:

| Variant | Points expressed relative to … |
|---|---|
| baseline | the sensor frame |
| translation | the proposal centre |
| yaw_alignment | the proposal centre, rotated by its yaw |
| canonical | the full canonical box frame |

Removing the global position and heading lets the refinement head learn one shape prior for "a car" instead of
one per location. That shows most clearly at range: recall at ≥ 40 m rose from 41 % to 66 %, and median yaw error
fell from 3.0° to 1.4°.

## What I learned

- **Representation beats capacity.** A coordinate change with no new parameters gave +13 AP on hard cars.
- **State the variance.** With a single seed, I reported the last-ten-epoch spread so readers can tell which
  differences are real.
- **Say what you didn't measure.** No test-set upload was made, so the page reports validation numbers only.
